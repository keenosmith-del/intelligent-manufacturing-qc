# MLOps lifecycle

Offline runs create versioned packages (`artifacts/<version>`) containing actual model.onnx, best.keras, metadata, evaluation, parity, class mapping, preprocessing, manifest and config. Content hashes version both dataset and held-out split; the model SHA-256 is verified again in Rust. Metadata includes framework, start/end timestamps, epoch history, calibration and failure examples. Training runs and evaluations are registered into Firestore separately; packages and images use local/GCS object storage.

Registration loads and executes the artifact, checks six output probabilities, preprocessing, checksum and parity metadata, and imports the package into the object store. It creates candidate metadata, training run, evaluation and audit records. A user-supplied report is trusted operator evidence, not cryptographic proof of honest training; registry access is privileged.

Release gates enforce macro-F1 >= `MIN_MACRO_F1` (default .5), each recall >= `MIN_CLASS_RECALL` (.2), validated executable output and export parity <=1e-5. Compare against active macro-F1 with maximum regression `MAX_F1_REGRESSION` (.03) only on identical dataset and split hashes. Incompatible evaluation is rejected, not compared. Synthetic releases require `ALLOW_SYNTHETIC=true` **and** Firestore emulator mode; they cannot activate in cloud mode.

Validation writes validated/rejected status and reason history. Activation always reruns checks, prepares the session, commits the active pointer and release/audit records, and swaps the actual in-memory session. Failure before commit leaves active state unchanged. Startup restores the persisted pointer. Rollback loads the previous validated version before committing a rollback. Already-running requests may complete with their captured prior session; every prediction reports the actual version used.

V1 uses a process mutex; **one backend instance** is required. Multi-instance distributed release/review coordination is not implemented. A crash after pointer commit is repaired by startup restoration. Immutable reviews preserve original predictions and supply future curation candidates. No automatic online retraining occurs. Export reviews, verify labels/permission, deduplicate against old training data, prepare a new dataset version, train and evaluate on a designated split, then register through the operator workflow. A changed evaluation dataset requires an explicit new baseline/service migration rather than bypassing comparison gates.

Monitoring derives class frequencies, confidence bins, mean/p95 latency, correction counts and agreement on selected reviewed labels from stored inspections. Process request/failure counters cover uploads since startup, including validation errors; they reset at restart and are labeled accordingly. Drift uses class-frequency population stability index (PSI) against the active model's test-prediction reference, requires 30 model-specific samples and warns above .2. This is a heuristic, not ground-truth performance or image-feature drift. Captured monitoring snapshots persist in Firestore.

Application CI runs deterministic tests, compilation and a small actual trained ONNX fixture, without retraining on each pull request. A separate manual ML workflow prepares, trains, evaluates, checks export/parity and packages new artifacts. Optional manual Cloud Run deployment uses GitHub OIDC/WIF and environment approval. Cloud deployment has not been executed.
